# Telegram заблокирован, а VPN мешает туннелю

Приложение может направлять только запросы бота через HTTP/SOCKS5-прокси. Для этого используется `BOT_PROXY_URL` в `.env`. Cloudflare-туннель продолжает подключаться отдельно. Эта настройка не включает VPN и не меняет маршруты Windows.

## Если VPN предоставляет локальный HTTP/SOCKS5-прокси

Подходит только VPN-клиент, у которого локальный прокси работает отдельно от TUN. Узнайте в его настройках **тип прокси и порт**. Названия могут быть HTTP, SOCKS, Mixed Port или Local Proxy. Номер порта нельзя угадывать.

1. Остановите старый запуск через Ctrl+C. Распакуйте новый архив в `G:\` с заменой исходников. Сохраните `.env`, `.venv`, `data` и `backups`.
2. Установите обновлённые зависимости:

   ```powershell
   cd G:\taoji-cargo
   .\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
   ```

3. Оставьте VPN-клиент и соединение с выбранным узлом включёнными. **Если локальный прокси может работать самостоятельно**, выключите глобальный TUN и системный прокси. Сам прокси должен отправлять Telegram через рабочий удалённый узел, а не в режиме Direct. Не закрывайте VPN-клиент.
4. Откройте `.env`:

   ```powershell
   notepad .env
   ```

   Добавьте или измените одну строку `BOT_PROXY_URL`. Например, **только если ваш HTTP-прокси действительно слушает порт 7890**:

   ```dotenv
   BOT_PROXY_URL=http://127.0.0.1:7890
   ```

   Если предоставляется SOCKS5, используйте `socks5://127.0.0.1:ВАШ_ПОРТ`, заменив `ВАШ_ПОРТ` реальным числом. Например, `socks5://127.0.0.1:1080` подходит **только при фактическом порте 1080**. HTTP и SOCKS5 — альтернативы: оставьте одну строку для своего типа прокси. Для Mixed Port можно использовать HTTP.

5. Сохраните файл и проверьте связь:

   ```powershell
   .\.venv\Scripts\python.exe scripts\check_telegram.py
   ```

   В начале должно быть «Telegram: подключение через BOT_PROXY_URL», затем успешная проверка токена. Команда не меняет бота и не отправляет сообщения.

6. Запустите:

   ```powershell
   .\start.bat
   ```

   После сообщения «Готово» откройте бота в Telegram, нажмите `/start` и кнопку приложения. Компьютер, VPN-клиент и окно запуска должны оставаться включёнными.

`BOT_PROXY_URL=` с пустым значением возвращает прямое подключение бота. Настройка применяется после перезапуска. Обычные значения `DEV_MODE=false`, `BOT_ENABLED=true` и `BOT_MODE=polling` для настоящего Mini App остаются прежними.

## Если VPN работает только через TUN

Поищите в вашем VPN функцию раздельной маршрутизации приложений — split tunneling. Нужно направить `G:\taoji-cargo\.venv\Scripts\python.exe` через VPN, а `cloudflared.exe` — напрямую. В этом варианте оставьте `BOT_PROXY_URL` пустым. Если клиент принимает пути к программам, путь к cloudflared можно посмотреть так:

```powershell
(Get-Command cloudflared).Source
```

Названия и наличие настроек зависят от VPN. Если функция отсутствует или kill switch блокирует прямое подключение, этот вариант может не сработать. Тогда требуется узнать точное название VPN-клиента и его возможности, прежде чем менять маршруты. Не отключайте VPN целиком: Telegram останется недоступен.

## Если всё ещё не запускается

| Результат | Что проверить |
|---|---|
| Неверный формат `BOT_PROXY_URL` | Схема `http://` или `socks5://`, адрес и явный числовой порт. В строке не должно остаться `ВАШ_ПОРТ` |
| `BOT_PROXY_DEPENDENCY` | Повторите установку `backend\requirements.txt` именно Python из `.venv` |
| `BOT_NETWORK` при включённом прокси | Правильный тип и порт; VPN-клиент запущен; выбранный узел доступен; правило Telegram направлено через узел |
| Проверка Telegram успешна, туннель не подключается | Убедитесь, что глобальный VPN/TUN действительно выключен либо cloudflared исключён. Для режима HTTP2 Cloudflare нужен исходящий TCP-порт 7844; не требуется открывать входящий порт на роутере |
| Telegram работает только через прокси внутри самого Telegram | MTProto-прокси вида `tg://proxy` не подходит для Bot API. Нужен HTTP/SOCKS5-прокси либо VPN-маршрут для Python |

Для дальнейшей диагностики достаточно названия VPN-клиента, типа/порта локального прокси и кода ошибки. Токен, `.env`, пароль прокси и ссылку подписки не пересылайте. Подробные коды запуска описаны в [DIAGNOSIS-WINDOWS.md](DIAGNOSIS-WINDOWS.md).

Документация компонентов: [прокси aiogram](https://docs.aiogram.dev/en/latest/api/session/aiohttp.html), [SOCKS5 и удалённое разрешение DNS](https://github.com/romis2012/aiohttp-socks), [сетевые требования Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-with-firewall/).
