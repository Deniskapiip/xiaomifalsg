# Этап 3 — админка на Windows

Инструкция для уже работающего проекта в `G:\taoji-cargo`. Архив содержит готовую сборку интерфейса; для быстрого обновления повторная установка зависимостей и сборка не нужны.

## Что мы сделали и зачем

Добавлена вкладка «Админка» для владельца и менеджера: обзор, все заказы, поиск и фильтры, смена статуса, итоговая доставка и внутренняя заметка. Владелец также меняет курс, комиссию и тарифы. В истории видны авторы изменений и даты МСК. Все экраны доступны в тёмной и светлой теме.

Роли определяются по **числовым Telegram ID** в `.env`: `OWNER_IDS` и `MANAGER_IDS`. Username используется для контакта, а не для прав. Если ID есть в обоих списках, действует роль владельца. Клиенту вкладка админки не показывается; сервер также проверяет права каждого запроса.

## Как проверить

### 1. Обновите работающий проект

В окне сервера нажмите `Ctrl+C`. Распакуйте архив в `G:\` с заменой файлов внутри существующей папки `G:\taoji-cargo`.

Обновите весь проект, включая `backend` и готовую папку `frontend\dist`. Backend теперь добавляет сведения об авторах в админские ответы: `events[].actor` и `rate_history[].changed_by_user`. Схема БД прежняя — дополнительных миграций на Этапе 3 нет.

Сохраните `.env`, `.venv` и `data`: их нет в архиве обновления. Не запускайте `setup_local.py` и seed повторно. Настройки и существующие заказы остаются в вашей БД.

Запустите сервер:

```powershell
cd G:\taoji-cargo\backend
..\.venv\Scripts\python.exe -m app.main
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) и нажмите `Ctrl+F5`. В локальном режиме, настроенном на Этапе 1, тестовый пользователь `900000001` имеет роль владельца. В нижнем меню должна появиться пятая вкладка **«Админка»**.

### 2. Проверьте заказы и статусы

Используйте тестовый заказ. Если подходящего нет, оформите его через клиентский мастер: цена `300 ¥`, количество `1`, демо-тариф `1 800 ₽ / кг`, вес `2,3 кг`.

1. Откройте «Админку» → «Обзор». Проверьте счётчики, заказы по статусам и новые за сегодня. Выберите «Оформляется» — откроется отфильтрованный список. В «Заказах» попробуйте поиск по номеру, фильтр статуса и сортировку.
2. Откройте заказ. Выберите «Выкуплен» и нажмите «Сохранить статус». Флажок «Уведомить клиента» по умолчанию включён. В локальном режиме `BOT_ENABLED=false`: событие и задание уведомления сохраняются, сообщение в Telegram не отправляется.
3. Выберите «Ожидает оплату доставки». В окне суммы укажите `4140` и сохраните. Для указанного выше демо-тарифа и веса это ориентировочная сумма. Проверьте итоговую доставку в админской и клиентской карточках.
4. Снова выберите тот же статус и укажите `4300`. Итоговая доставка должна обновиться, а обе суммы — остаться в истории изменений.
5. Попробуйте откат на «Выкуплен»: появится подтверждение. Отмените окно и убедитесь, что статус не изменился; затем повторите и подтвердите. Выбор «Отменён» тоже требует подтверждения. Используйте отмену только для тестового заказа.
6. Сохраните внутреннюю заметку, например «Проверить цвет перед выкупом». Она видна в админке и её истории. Перейдите в «Мои заказы» и откройте этот же собственный тестовый заказ: заметка и события заметок клиенту не показываются.
7. Проверьте автора и время в админской истории, затем переключите тему кнопкой в шапке. Повторите просмотр списка, карточки и окна доставки в другой теме.

### 3. Проверьте настройки владельца

Перед изменениями запишите текущие значения, чтобы вернуть их после проверки.

- В «Настройках» укажите тестовый курс `13,75`, проверьте поля процента и минимальной комиссии и сохраните. В истории курса должны появиться старое и новое значения, автор и дата. Для проверки полей комиссии можно временно изменить их и сохранить, затем вернуть прежние значения.
- Откройте расчёт нового заказа: он использует текущие настройки. Сохранённый расчёт ранее оформленного заказа должен остаться прежним. После проверки верните нужные рабочие значения.
- В «Тарифах» откройте существующий демо-тариф, измените название, цену или порядок и сохраните. Меньший номер порядка показывается раньше. Снимок тарифа в существующем заказе не меняется.
- Снимите отметку «Активен» и сохраните: тариф останется в админке, но исчезнет из выбора для новых заказов. Затем при необходимости включите его обратно.
- Создайте «Проверочный тариф» с положительной тестовой ценой, задайте порядок и включите его. Проверьте появление в мастере заказа. После проверки отключите этот тариф. Тестовые цены и названия не являются бизнес-условиями; реальные сроки и описания заполняет владелец.

### 4. Необязательная локальная проверка ролей

Эти действия относятся к локальному режиму `DEV_MODE=true`, `BOT_ENABLED=false`, `WEBAPP_URL=http://127.0.0.1:8000`. Для настоящего Telegram используйте реальные ID без подмены тестового пользователя.

Сначала остановите сервер и сохраните копию настроек:

```powershell
cd G:\taoji-cargo
Copy-Item -Path .env -Destination .env.stage3-backup
```

Редактируйте `.env` вручную. Не удаляйте уже настроенные реальные ID владельцев и менеджеров. Примерные ID ниже используются только для локального теста; если они уже есть в ваших списках, выберите другие свободные положительные числовые ID.

| Проверяемая роль | Временное изменение | Ожидаемое поведение |
|---|---|---|
| Менеджер | `DEV_USER_TG_ID=900000002`; добавить `900000002` в конец `MANAGER_IDS` через запятую, сохранив прежние ID; этот ID не должен быть в `OWNER_IDS` | Видны админский обзор, все заказы, статусы, сумма доставки и заметка. Настройки и тарифы владельца недоступны. |
| Клиент | `DEV_USER_TG_ID=900000003`; этот ID не добавлять ни в `OWNER_IDS`, ни в `MANAGER_IDS` | Нет вкладки «Админка». В «Моих заказах» только заказы этого тестового пользователя. |

После каждого изменения перезапустите сервер и обновите браузер через `Ctrl+F5`. Новый тестовый пользователь создаётся при локальном входе; повторный seed не нужен.

Когда закончите, остановите сервер и восстановите исходные настройки:

```powershell
cd G:\taoji-cargo
Copy-Item -Path .env.stage3-backup -Destination .env -Force
cd backend
..\.venv\Scripts\python.exe -m app.main
```

Обновите страницу через `Ctrl+F5`. Проверка ролей создаёт тестовых пользователей, но не меняет ID существующих клиентов. Копия `.env` содержит секреты: храните её так же, как исходный файл.

Для реальных администраторов узнайте числовые ID через `@userinfobot`, внесите их в соответствующие списки `.env` и перезапустите сервер. Оба администратора должны нажать `/start` у вашего бота, чтобы получать уведомления. Настройка туннеля и проверка настоящих сообщений на телефоне — Этап 4.

## Что может пойти не так и что делать

| Проблема | Что сделать |
|---|---|
| Вкладки «Админка» нет | Проверьте числовой ID текущего пользователя и списки `OWNER_IDS` / `MANAGER_IDS`, затем перезапустите backend и нажмите `Ctrl+F5`. В локальном тесте текущий ID задаёт `DEV_USER_TG_ID`. |
| Менеджер видит настройки владельца | Его ID также находится в `OWNER_IDS`. Для отдельного тестового менеджера выберите ID, которого там нет; настоящие ID владельцев сохраняйте. |
| Интерфейс остался прежним | Проверьте, что обновлена `G:\taoji-cargo\frontend\dist`, затем нажмите `Ctrl+F5`. |
| Автор истории не отображается | Обновите исходники backend из этого же архива и перезапустите сервер. |
| «Недостаточно прав» после изменения роли | Обновите страницу после перезапуска. Настройки и тарифы доступны только владельцу. |
| Кнопка статуса неактивна | Выберите другой статус. Для «Ожидает оплату доставки» повторное сохранение доступно, чтобы изменить сумму. |
| Сумма доставки не принимается | Введите положительное целое число рублей без валюты и разделителей, например `4140`. |
| После сохранения нет сообщения в Telegram | При `BOT_ENABLED=false` отправки отключены. Для реального бота нужны действующий токен, HTTPS-адрес и `/start` получателя; телефонная проверка ещё предстоит. |
| Сохранение завершилось сетевой ошибкой | Нажмите предложенную проверку данных и сверяйте сохранённое значение перед повтором. Для нового тарифа сначала проверьте список, чтобы не создать дубликат. |
| Тариф не появляется у клиента | Проверьте отметку «Активен» и положительную цену, сохраните, затем обновите страницу клиента. |
| Порт 8000 занят | Остановите старый сервер через `Ctrl+C` и запустите один экземпляр. |

Для установки с нуля и самостоятельной пересборки интерфейса используйте [README.md](README.md).
