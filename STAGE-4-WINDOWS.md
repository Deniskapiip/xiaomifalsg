# Этап 4 — запуск на Windows и настоящий Telegram

Проект уже находится в `G:\taoji-cargo`. Этот этап добавляет запуск двойным кликом, бесплатный HTTPS-туннель и резервные копии SQLite. Проверку на вашем Windows и в Telegram на телефоне вы выполняете по этой инструкции: здесь она ещё не пройдена.

## Что мы сделали и зачем

- `start.bat` запускает `scripts\dev.py`: проверяет окружение, делает резервную копию, получает HTTPS-адрес Quick Tunnel и запускает backend с ботом. Интерфейс берётся из готового `frontend\dist`.
- `scripts\setup_telegram.py` помогает настроить настоящий бот: токен вводится скрыто, права задаются числовыми ID. Секреты сохраняются в `.env` и не выводятся в инструкции или адресе приложения.
- Локальный режим позволяет продолжать браузерную разработку без туннеля. Проверка `--check` показывает готовность без запуска и изменения настроек.
- Новые заказы тестового пользователя в локальном режиме не отправляют сообщения в Telegram, даже после включения настоящего бота. Старые немаркированные заказы сохраняются без изменений; приёмку уведомлений проводите на новых заказах из Telegram.
- `scripts\backup.py` делает согласованную копию SQLite, в том числе при работающем сервере. В `backups` остаются 14 последних копий.

Публичный тест работает, пока включены ваш ПК, приложение и туннель. Cloudflare Quick Tunnel не требует аккаунта или собственного домена; адрес меняется при каждом новом туннеле. Он предназначен для тестирования, без гарантии доступности: максимум 200 одновременно выполняемых запросов, без SSE. В этом приложении обновление заказов работает обычными запросами. [Официальная документация Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## Как проверить

### 1. Обновите проект и установите cloudflared

Остановите старый сервер через `Ctrl+C`. Распакуйте архив в `G:\` с заменой исходников внутри `G:\taoji-cargo`, включая backend, scripts, `start.bat` и готовый `frontend\dist`.

Сохраните `.env`, `.venv`, `data` и имеющиеся `backups`. Они не входят в архив обновления. Повторная настройка БД, seed и миграции на этом этапе не нужны. Для запуска готовой сборки Node.js не требуется.

В PowerShell выполните:

```powershell
winget install --id Cloudflare.cloudflared --exact --source winget
```

Откройте новый PowerShell, чтобы обновился PATH, и проверьте:

```powershell
cloudflared --version
cd G:\taoji-cargo
```

Уже установленный cloudflared повторно устанавливать не нужно. Проверка приложения выполняется после настройки настоящего бота ниже.

### 2. Подготовьте бота в BotFather

Если бот уже создан, используйте его — новый не нужен. Откройте [@BotFather](https://t.me/BotFather).

| Команда | Что сделать и зачем |
|---|---|
| `/newbot` | Только для нового бота: имя `Taoji Cargo`, свободный username с окончанием `bot`. BotFather выдаст токен для подключения к API. |
| `/setuserpic` | Выберите бота и отправьте `frontend\public\logo.png`: логотип появится в списке чатов. |
| `/setdescription` | Коротко опишите выкуп товаров, оформление и просмотр статусов: этот текст виден перед началом общения. Сроки и условия уточняются у менеджера. |
| `/setabouttext` | Укажите короткое описание сервиса для профиля бота. |
| `/setcommands` | Добавьте список ниже, чтобы Telegram показывал подсказки команд. Код также обновит их при запуске. |

```text
start - Начать работу
app - Открыть приложение
orders - Мои заказы
help - Помощь и контакты
```

Сохраните токен для следующего шага. Не отправляйте его в чат, URL или скриншот. [BotFather: официальная инструкция](https://core.telegram.org/bots/features#botfather).

Владелец и, если он есть, менеджер должны узнать каждый свой **числовой ID** через [@userinfobot](https://t.me/userinfobot). `@ZontikTech` и `@TaojiBuy` — контакты; права задают числа. После запуска каждый администратор должен открыть вашего бота и нажать `/start`, чтобы бот мог ему писать.

### 3. Настройте настоящий Telegram

В папке проекта запустите:

```powershell
cd G:\taoji-cargo
.\.venv\Scripts\python.exe scripts\setup_telegram.py
```

Введите токен в скрытом поле; Enter оставляет текущий токен. Затем укажите полный список реальных числовых ID владельцев и менеджеров через запятую. Нужен хотя бы один владелец; менеджеры необязательны. Enter в поле менеджеров означает пустой список и удаляет прежние права менеджеров.

Мастер показывает сводку и просит подтверждение. Списки `OWNER_IDS` и `MANAGER_IDS` заменяются подтверждёнными списками: включите в них всех нужных настоящих администраторов, а старые локальные тестовые ID исключите. Существующий корректный `JWT_SECRET` сохраняется; если он отсутствует или является заглушкой, мастер создаёт новый. Подключение БД и настройки расчёта сохраняются. Если один человек выполняет обе роли, роль владельца имеет приоритет. Для полной приёмки прав понадобится отдельный аккаунт менеджера.

Для публичного запуска используются `ENV=development`, `DEV_MODE=false`, `BOT_ENABLED=true`, `BOT_MODE=polling`. Временный `WEBAPP_URL=https://setup-pending.invalid` — заглушка подготовки, по ней приложение не открывается. Рабочий адрес запишет launcher после запуска туннеля. `JWT_SECRET` остаётся отдельным секретом, а не токеном бота.

Теперь проверьте готовность:

```powershell
.\.venv\Scripts\python.exe scripts\dev.py --check
```

Проверка не печатает токен, не изменяет `.env` и не создаёт копий. Она проверяет настройки и локальные файлы; действительность токена и соединение с Telegram и Cloudflare проверяются при обычном запуске.

### 4. Запустите двойным кликом

Откройте `G:\taoji-cargo\start.bat` двойным кликом. Равнозначная команда:

```powershell
cd G:\taoji-cargo
.\.venv\Scripts\python.exe scripts\dev.py
```

Перед запуском сохраняется резервная копия SQLite. Launcher получает HTTPS URL Cloudflare, обновляет `WEBAPP_URL` и запускает FastAPI и polling-бота. Бот устанавливает команды и кнопку меню с новым URL. Каждый раз вручную менять Menu Button в BotFather не нужно.

Сообщение «Готово» выводится после успешной проверки локального и публичного `/api/health`. При ошибке 1033 launcher покажет её и остановит свои процессы. Другой транспорт Cloudflare: `.\start.bat --tunnel-protocol auto` (по умолчанию используется HTTP2). Диагностика и резервный туннель: [TUNNEL-1033-WINDOWS.md](TUNNEL-1033-WINDOWS.md).

Оставьте окно открытым. Остановка — `Ctrl+C`: launcher завершает запущенные им backend и туннель. Для остановки используйте эту комбинацию, а не закрытие окна крестиком. После перезапуска используйте свежую кнопку меню или новую команду `/app`: ссылки в старых сообщениях могут содержать прошлый адрес туннеля.

В Telegram:

1. Владелец, менеджер и тестовые клиенты открывают вашего бота и нажимают `/start`.
2. Нажмите кнопку приложения в меню бота или отправьте `/app`.
3. Пройдите сценарии из [ACCEPTANCE-TELEGRAM.md](ACCEPTANCE-TELEGRAM.md). Теперь проверяются настоящий вход, роли и сообщения, а не локальная подмена пользователя.

Для этого теста достаточно меню бота. Кнопка **Main Mini App** в профиле — отдельная необязательная настройка BotFather: launcher обновляет Menu Button, а профильную ссылку автоматически не меняет. Не сохраняйте в профиле устаревающий Quick Tunnel URL без последующего ручного обновления. [Способы запуска Mini Apps](https://core.telegram.org/bots/webapps).

### 5. Локальная разработка и внешний HTTPS-адрес

Все режимы запускайте из `G:\taoji-cargo`; одновременно работает один backend.

| Режим | Команда | Назначение |
|---|---|---|
| Quick Tunnel | `.\.venv\Scripts\python.exe scripts\dev.py` | Обычный запуск для проверки настоящего Telegram. |
| Только локально | `.\.venv\Scripts\python.exe scripts\dev.py --local` | Браузерный dev-вход на `http://127.0.0.1:8000`, без публичного туннеля. |
| Локальный владелец | `.\.venv\Scripts\python.exe scripts\dev.py --local --local-role owner` | Проверить админку с временными правами только в дочернем процессе. |
| Готовый внешний адрес | `.\.venv\Scripts\python.exe scripts\dev.py --url https://YOUR_HTTPS_HOST` | Использовать уже работающий HTTPS-туннель на локальный порт приложения. Замените адрес своим. |
| Только проверка | `.\.venv\Scripts\python.exe scripts\dev.py --check` | Проверить готовность без запуска, резервирования и изменения `.env`. |

`--local` временно включает dev-вход, отключает бота и задаёт loopback-адрес только процессу приложения; `.env` не меняется. Без `--local-role` роль тестового пользователя определяется существующими списками в `.env`: после настройки настоящего Telegram обычно это клиент. Для проверки конкретной роли добавьте `--local-role owner`, `--local-role manager` или `--local-role client`. Эти параметры меняют права тестового ID только дочернему процессу; списки в `.env` сохраняются. После остановки процесса временные права исчезают; параметры относятся только к локальному режиму.

Для изменения интерфейса можно запустить локальный backend через `--local` (или `--local --local-role owner` для админки), затем в другом PowerShell:

```powershell
cd G:\taoji-cargo\frontend
npm.cmd ci
npm.cmd run dev
```

Откройте `http://127.0.0.1:5173`. Vite передаёт `/api` на backend. Оба процесса остаются на loopback; этот режим не выставляется в публичный туннель. Нужный `DEV_MODE` launcher задаёт временно. Права настоящих администраторов не заменяйте тестовыми в `.env`.

Адреса в примерах используют стандартный `PORT=8000`. Если изменяли порт backend, используйте его в адресах и обновите `/api` proxy в `frontend\vite.config.ts` для запуска через Vite.

Если Cloudflare недоступен, можно использовать бесплатный ngrok с аккаунтом. Установите его по [официальной инструкции для Windows](https://ngrok.com/download/windows), например:

```powershell
winget install ngrok -s msstore
```

Откройте новый PowerShell. Создайте бесплатный аккаунт ngrok и получите его authtoken. Затем запустите помощник проекта:

```powershell
cd G:\taoji-cargo
.\.venv\Scripts\python.exe scripts\ngrok_tunnel.py
```

Помощник читает `NGROK_AUTHTOKEN` из `.env`; если его нет, предлагает скрытый ввод и сохранение после подтверждения. Токен не передаётся в строке команды и не публикуется. Возьмите HTTPS URL из окна ngrok. В **другом** PowerShell запустите backend, заменив адрес своим:

```powershell
cd G:\taoji-cargo
.\.venv\Scripts\python.exe scripts\dev.py --url https://YOUR_NGROK_HOST
```

Оба окна оставьте открытыми. Помощник ngrok использует порт из настроек проекта; по умолчанию это 8000. Отдельный `ngrok config add-authtoken` для этого способа не нужен — секрет остаётся в `.env`.

На бесплатном ngrok перед HTML может появиться страница предупреждения. Нажмите **Visit** в том же Telegram WebView, если она появилась. Открытие в отдельном браузере не гарантирует, что cookie перенесётся в WebView. Дополнительный экран может мешать автоматической загрузке Mini App — тогда используйте Cloudflare. Не требуется покупать тариф для этой проверки. [Ограничения бесплатного ngrok](https://ngrok.com/docs/pricing-limits/free-plan-limits).

### 6. Резервные копии и восстановление

Каждый обычный локальный или публичный запуск создаёт online backup SQLite в `G:\taoji-cargo\backups`. Имена имеют вид `taoji-YYYYMMDD-HHMMSS-microseconds-8hex.db`. Сохраняются 14 последних файлов этого помощника; чужие файлы в папке не удаляются. Проверка `--check` копий не создаёт. Ежедневного фонового расписания нет: для дополнительной копии используйте ручную команду.

Дополнительная копия вручную, без остановки сервера:

```powershell
cd G:\taoji-cargo
.\.venv\Scripts\python.exe scripts\backup.py
```

Это самостоятельный файл БД. Обычное копирование работающего `data\taoji.db` без учёта WAL не заменяет online backup.

Восстановление выполняйте вручную. Ниже предполагается стандартная БД `data\taoji.db`; если изменяли `DATABASE_URL`, используйте фактический путь.

1. Остановите приложение, туннель и все программы, работающие с этой БД. Сделайте дополнительную резервную копию текущего состояния командой выше.
2. Выберите нужную копию в `backups`. Переместите прежние `data\taoji.db` и, если существуют, `data\taoji.db-wal` и `data\taoji.db-shm` в отдельную временную папку. Это сохранение прежних файлов, а не источник восстановления.
3. Скопируйте **один файл online backup** в `data` и переименуйте в `taoji.db`. Рядом не должны оставаться WAL/SHM от прежней БД.
4. Запустите `start.bat` и проверьте нужные заказы. Восстановление возвращает БД к моменту выбранной копии; более поздние изменения останутся только в сохранённом прежнем состоянии.

Резервные копии на том же диске помогают при ошибках приложения, но не при потере диска. При необходимости перенесите согласованную копию в своё дополнительное хранилище. `.env` хранится отдельно и содержит секреты; не публикуйте его вместе с архивом проекта.

## Что может пойти не так и что делать

| Проблема | Что сделать |
|---|---|
| `winget` не найден | Установите или обновите «Установщик приложений» Microsoft и откройте новый PowerShell. |
| `cloudflared` не найден | Установите пакет, затем откройте новый PowerShell и проверьте `cloudflared --version`. |
| Нет `.env` или виртуального окружения | Для первой установки используйте README. При обновлении проверьте, что сохранили прежние `.env` и `.venv` и не создали лишнюю вложенную папку проекта. |
| `start.bat` быстро закрылся или текст нечитаем | Запустите Python-команду `scripts\dev.py` из уже открытого PowerShell: ошибка останется в окне. Не вставляйте в чат токены или содержимое `.env`. |
| Порт 8000 занят | Остановите старый backend через `Ctrl+C`; приложение работает в одном экземпляре. Если только что остановили сервер, подождите несколько секунд и повторите. |
| `FRONTEND_NOT_BUILT` | Верните `frontend\dist` из архива или выполните `npm.cmd ci` и `npm.cmd run build` в `frontend`. |
| Cloudflare не получает адрес, ошибка DNS/сети | Проверьте интернет, доступ к Cloudflare и свежий cloudflared. Повторите запуск; при необходимости используйте свой HTTPS-туннель через `--url`. |
| Старая ссылка туннеля не открывается | Запустите launcher и откройте новую кнопку меню или `/app`. Quick Tunnel URL меняется после перезапуска. |
| Ошибка `BOT_TOKEN`, Unauthorized или 401 от Telegram API | Проверьте токен в скрытом мастере `setup_telegram.py`, затем перезапустите launcher. При отзыве токена в BotFather используйте новый. |
| Telegram не открывает HTTP или сообщает о TLS | Для настоящего Telegram нужен действующий HTTPS URL с корректным сертификатом; `localhost` телефона не означает ваш ПК. |
| Ошибка `initData` или истёк вход | Закройте Mini App и заново откройте из меню бота. Проверьте автоматическую синхронизацию даты и времени Windows. Не открывайте публичный URL в браузере для обхода Telegram-входа. |
| Конфликт polling / бот не отвечает | Не запускайте два экземпляра с одним токеном; остановите прежний процесс. Polling и webhook одновременно не используются. |
| Нет админки | Проверьте реальные числовые ID в `OWNER_IDS` / `MANAGER_IDS`, перезапустите сервер и заново откройте приложение. |
| Клиент не получает уведомление | Он должен нажать `/start` или разрешить сообщения и не блокировать бота. Проверьте результат в админской карточке и при необходимости свяжитесь вручную. |
| ngrok показывает предупреждение вместо приложения | Пройдите **Visit** в том же WebView либо используйте Cloudflare. На бесплатном плане предупреждение предусмотрено ngrok. |
| Бэкап не создаётся | Проверьте свободное место и доступ на запись в `backups`, закройте редакторы БД и повторите ручную команду. Не удаляйте рабочую БД для устранения ошибки. |

Для первой установки и пересборки нужен Python 3.13 и, для frontend, Node.js 24 LTS. Команды установки сохранены в [README.md](README.md). Синтаксис winget: [Microsoft Learn](https://learn.microsoft.com/en-us/windows/package-manager/winget/install); идентификаторы пакетов — [официальный каталог Microsoft](https://github.com/microsoft/winget-pkgs).
