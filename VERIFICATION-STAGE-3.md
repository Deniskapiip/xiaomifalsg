## Браузерные сценарии

- Сводка со счётчиками по статусам и предупреждением владельцу о курсе старше 24 часов.
- Поиск по номеру/ссылке, сортировка, две страницы результатов; возврат из карточки сохраняет поиск и порядок списка.
- Карточка клиента, снимок выкупа и тарифа, история с именами авторов и датами МСК.
- Внутренняя заметка сохраняется; незавершённый ввод не заменяется при обновлении заказа. Заметка, события заметок и поля авторов отсутствуют в клиентском API и клиентском экране.
- Флажок уведомления по умолчанию включён. Проверка операций выполнялась с notify=false и отключённым ботом.
- Ожидание оплаты доставки открывает окно суммы; нулевая сумма не проходит. Повторное сохранение меняет итоговую доставку с 4200 на 4300 ₽ и сохраняет историю.
- Откат статуса и отмена требуют подтверждения; отмена окна не меняет статус. Native BackButton закрывает окно подтверждения.
- Если другой администратор успел изменить статус и сервер ответил CONFIRMATION_REQUIRED, данные обновляются и переход требует нового явного подтверждения.
- После обрыва ответа уже сохранённый статус проверяется отдельным запросом; повтор заблокирован до проверки. В истории остаётся одна смена на «Доставлен», прогресс равен 100%.
- Настройки принимают запятую и точку. После обрыва ответа проверка подтверждает все три сохранённых значения без повторного PUT. История содержит автора. Старый заказ остаётся 4700 ₽; новый при курсе 13.75 — 4775 ₽.
- Активный тариф с нулевой ценой не сохраняется. Создание после потери ответа блокируется до проверки списка; найденный новый тариф открывается для редактирования. Сортировка учитывает порядок и ID при равенстве. Отключённый тариф остаётся у владельца и исчезает из клиентского выбора.
- Ссылка из уведомления открывает админскую карточку у владельца/менеджера и собственную карточку у клиента. Явная ссылка из «Моих заказов» сохраняет клиентский вид.
- Менеджер видит два раздела: обзор и заказы; настройки, тарифы и финансовые суммы владельца скрыты. API владельца возвращает менеджеру 403. Клиент не видит вкладку админки.

## Новые автоматические проверки

Frontend: границы и точность курса/комиссии/минимума и тарифов; положительная целая доставка; подтверждения по порядку статусов; ограничения маршрутов для ролей; ссылки и возврат фильтров; приватность кеша; обновление роли при 403 без повторной отправки запрещённой операции.

Backend: авторы админской истории и истории курса, отсутствие приватных полей у клиента, системный автор null и загрузка нескольких авторов одним запросом. Предыдущие проверки расчёта, прав, уведомлений и идемпотентности также проходят.

## Ограничения и следующий этап

Настоящие Telegram-уведомления, Android/iOS, HTTPS-туннель и запуск на Windows одним действием проверяются на Этапе 4. Изменения данных требуют явного сохранения; приложение не повторяет административные операции автоматически после потери ответа. Отчёт не заменяет проверку с настоящим ботом и реальными ID.
