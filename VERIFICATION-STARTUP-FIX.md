# Диагностика ошибки запуска — 13.10.2026

Проблема: старый launcher скрывал stderr/stdout дочернего backend и выдавал одну общую ошибку. По пользовательскому сообщению причина падения backend пока не определена.

Исправление: этапы проверки токена, команд, кнопки Mini App, режима polling/webhook и базы теперь передают только заранее известный код. Launcher читает его независимо от переполненной очереди вывода и показывает статическое сообщение. Строки внешних исключений, токены и webhook URL не выводятся. После выхода дочернего процесса читателю даётся до 0,5 секунды, чтобы получить последний маркер.

Каждый запрос настройки бота ограничен 10 секундами; это не меняет timeout обычной отправки уведомлений. При зависшем запросе формируется BOT_NETWORK вместо ожидания дольше проверки готовности launcher.

Добавлена самостоятельная scripts/check_telegram.py: getMe и getWebhookInfo, без изменения бота или базы. Токен читается локально из .env, не передаётся в командной строке и не печатается.

Проверки: 24 новых backend-проверки этапов и исключений, 12 новых launcher-проверок и 7 проверок standalone checker/зависшего запроса. Использованы подменённые Telegram-клиенты и настоящие локальные дочерние процессы для проверки чтения маркеров. Проверены скрытие секретов даже в traceback, очередь полного размера, запоздалое чтение и malformed marker.

До последнего ограничения timeout полный набор прошёл на Python 3.11 и 3.13: 274 passed, 4 skipped. После добавления проверки зависшего запроса полный набор на Python 3.13: 275 passed, 4 skipped. Пропуски — прежние PostgreSQL интеграционные тесты; они к этой ошибке запуска не относятся.

Настоящий токен пользователя, его сеть и Windows здесь недоступны. Для определения фактической причины запустите checker и обновлённый start.bat по DIAGNOSIS-WINDOWS.md. Успешная подготовка туннеля не доказывает доступность Telegram API.
